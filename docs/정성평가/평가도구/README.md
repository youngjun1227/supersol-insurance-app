# 평가도구 — 우리가 만드는 것

9/11 당일 진행자와 참가자가 실제로 쓰는 물건. **테스트 전에 완성돼야 한다.**

## 만들 것

| 파일 | 무엇 | 상태 |
|---|---|---|
| `평가지.md` | 참가자 주관 평가 — **비교 지표 2개 중 하나** | ✅ 도입 3 + 본문 29 |
| `survey-app/` | 평가지의 웹 구현 — 참가자가 직접 입력 · CSV | ✅ `npm run build` → `dist/index.html` |
| `진행자-스크립트.md` | 읽는 그대로 말하는 대본 · 막혔을 때 문장 · 세션 후 절차 | ✅ |
| `채점기준.md` | 성공/실패 판정 · 평균 금지 · A/B 분리 | ✅ (이슈 #119) |
| `동의서.md` | 녹음·기록 동의 — 인쇄본 | ✅ |

## 평가지가 이 폴더의 핵심이다

리허설이 평가지를 기다리느라 **0회**다 (9/8 마지노선). 여기가 밀리면 리허설이 밀리고
리허설이 밀리면 9/10 프리즈에 걸린다.

## 만들 때 지킬 것

- **양쪽에 똑같이 쓸 수 있어야 한다.** 기존 슈퍼쏠에도 그대로 물을 수 있는 문항만 —
  우리 화면 이름("보장진단")이 문항에 들어가면 기존 앱에서 못 묻는다
- **유도 질문 금지.** "개선된 화면이 더 편했나요" 는 답이 정해진 질문이다
- 문구는 참가자가 읽는 것이라 **"~해요"체**로 (CLAUDE.md 문구 규칙)
- "개선안"·"솔루션"·"MVP"·팀명 금지 — 참가자에게 우리 편을 알리지 않는다

## 진행자가 여러 명이면

채점 기준이 없으면 진행자마다 성공 판정이 갈린다 (이슈 #119). 특히 `premium` 의
"35,000원" 을 **"3만 5천 원 정도"** 라고 답하면 성공인가 — 이런 걸 미리 적어 둔다.
