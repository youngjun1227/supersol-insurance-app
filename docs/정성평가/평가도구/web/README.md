# 평가지 웹 — 참가자 직접 입력용

`survey.html` 파일 하나다. 서버·빌드·설치가 필요 없다. 더블클릭하면 브라우저에서 열린다.

**참가자가 직접 입력한다. 진행자 판정 칸은 화면에 없다.** 정오·근거 채점은 CSV 를 보고 사후에 한다
(2026-09-04 팀장 결정 — 참가자 화면에 정답 힌트가 남는 걸 막기 위해). 과제 성공은 참가자 자기보고(Q0)로 받는다.

```
시작 화면 (참가자 번호 · 순서 · 진행자)
  배경 B1~B2

[표지] 아이디어 1 · 상품 찾기        ← 역할 없음, 실기기, 순서는 홀짝 교차
  Task1  Q0 자기보고 → Q1~Q3  — 신한라이프·타사 치아보험 각 1개 (대응비교)
[표지] 아이디어 1 · 상품 상세 살펴보기  ← Task1 이 끝난 뒤에야 보인다
  Task2  G1·G1b → (분기) G2~G6 또는 G7  — 상품 상세 에이전트, 참가자가 직접 분기

[표지] 아이디어 2 · 보험 탭 홈 개인화   ← 역할 부여 (보험 2개 20대)
  역할 안내 → 화면1 (P1~P5 한 페이지) → 화면2 (P1~P5 한 페이지) → C1~C4

[표지] 아이디어 3 · 보장진단          ← 역할 유지(되짚기만)
  역할 되짚기 → 이름만 보고 T1~T4 → T5
  → 서비스1 A1~A7 → 서비스2 A1~A7 → E1~E2 → D1~D4

마무리 F1~F3
종료 화면 → CSV
```

총 49단계(G1b "눌러봤다"면 53). 순서는 참가자 번호로 자동 — **홀수 = 기존 먼저, 짝수 = 우리 먼저**, 세 아이디어 공통.

## 화면 이미지를 보는 방식 — 폰 프레임

UI 스크린샷은 세로로 길다(393×1674). 축소해 끼우면 띠가 되므로 **원본 폭 그대로 폰 프레임 안에 넣고,
프레임 안을 실제 폰처럼 위아래로 넘긴다.** "크게 보기"를 누르면 전체 화면(역시 스크롤).

- **아이디어 2 화면 단계는 화면 하나당 한 페이지** — 프레임을 보면서 P1~P5 를 이어서 답한다. 문항마다 페이지가 바뀌면 매번 화면을 다시 찾아야 해서 합쳤다
- **폰(좁은 화면)**: 프레임이 위에 붙어(sticky) 문항을 내려가며 답해도 사라지지 않는다. "화면 접기"로 접을 수 있다
- **태블릿·노트북(900px 이상)**: 왼쪽에 프레임 고정, 오른쪽에 문항 — 9/11 진행은 이 폭이 편하다
- C1·C2 는 두 프레임을 나란히(폰) / 위아래로(넓은 화면) 보여준다
- 이름표("첫 번째 화면")는 프레임 **위 띠**에 있다 — 스크린샷 위에 얹으면 앱 헤더를 가린다
아이디어 4(청구)는 아직 미포함 — 개정 끝나면 붙인다.

## 진행 중 자동 저장

매 입력·이동마다 `localStorage`(`sol_survey_v2_draft`)에 임시 저장한다. 탭이 죽거나 새로고침해도
다시 열면 시작 화면에 **"진행 중이던 응답이 있어요 — 이어서 하기 / 버리기"** 가 뜬다.
제출하면 임시본은 지워진다. 같은 브라우저에서만 이어진다.

## 미응답 방어

선택형·척도를 빈 채로 "다음"을 누르면 한 번 확인한다. **G1b(분기점)는 답을 고르기 전엔 넘어갈 수 없다.**
주관식은 막지 않는다. G1b 답을 되돌아가 바꾸면 반대 분기에 남아 있던 답은 자동으로 비운다.

## 배경 B1~B2 — 맨 앞

참가자가 보험이 없어 옛 도입(전제 검증)은 못 쓴다. 사전 지식 차이만 잡는다 — P1·A 답을 해석할 때 쓴다.

| | 문항 | 형식 |
|---|---|---|
| **B1** | 보험 관련 앱·서비스를 써본 적 + 무엇을 | 3지 + 한 줄 |
| **B2** | 가족이 대신 들어준 보험이 있는지 아는가 | 3지 |

## 아이디어 1 · 상품 찾기 — 역할 없음, 실기기, 블라인드 아님

### Task 1 — 상품 찾기 (대응비교)

과업: "신한라이프 치아보험 1개, 타사 치아보험 1개를 찾아서 각각 열어봐 주세요." 표지에 **어느 앱을 먼저 할지**가 뜬다.

| | 문항 | 형식 |
|---|---|---|
| **Q0** | 두 상품을 다 찾았나 — **자기보고** | 둘 다/하나만/못 찾았다, 기존·두 번째 각각 |
| **Q1** | 두 상품을 찾기 얼마나 쉬웠나 | ①~⑤, 기존·두 번째 각각 |
| **Q2** | 탐색·비교하기에 더 편리했던 쪽 | 기존/두 번째/비슷/모르겠다 |
| **Q3** | 그렇게 느낀 이유 | 주관식 |

진행자가 종이(`평가지.md` 진행자 기록란)에 성공/실패를 따로 적으면 Q0 와 대조할 수 있다 — 백업이지 필수는 아니다.

### Task 2 — 상품 상세 에이전트 (자유 발견, 분기형)

과업: "**두 번째 화면에서**, 방금 열어본 상품의 상세 화면으로 돌아가 이 상품에 대해 궁금한 걸 직접 알아봐 주세요. 어떤 방법을 써도 됩니다."

**Task1 표지에는 Task2 가 보이지 않는다.** 미리 알면 "스스로 발견했는지"가 오염된다.
**진행자는 개입하지 않는다.** "눌러보세요"라고 안내하지 않는다.

| | 문항 | 형식 |
|---|---|---|
| **G1** | 방금 그 정보를 어떻게 찾았나 | 주관식 |
| **G1b** | 마스코트·말풍선 버튼을 눌러봤나 — **분기점, 필수** | 눌러봤다 / 못 봤거나 안 눌러봤다 |

"눌러봤다" → **G2** 처음 봤을 때 뭐로 보였나 · **G3** 왜 이 질문이 먼저 나왔다고 생각하나 · **G4** 답변 아래 문구를 기억하나 · **G5** 실제로 쓸 것 같나 + 이유 · **G6** 아쉽거나 불편했던 점
"못 봤거나 안 눌러봤다" → **G7** 마스코트를 봤나, 봤는데 안 눌렀다면 왜

밟지 않은 쪽 문항은 CSV 에 **N/A** 로 찍힌다.

## 아이디어 2 · 보험 탭 홈 개인화 — 역할 부여, 스크린샷 2장, 블라인드

재는 건 "찾기 쉬운가"가 아니라 **"이 화면이 내 얘기인가"** — 개인화 요소 4개
(보험 현황 · 메뉴 묶음 · 보장진단 · 추천)가 각각 인지됐는지.

| | 문항 | 형식 |
|---|---|---|
| **P1** | 이 화면은 어떤 사람한테 보여주는 화면 같은가 | 주관식 |
| **P2** | 나에게 맞춰졌다고 느껴지는 부분 | 주관식 |
| **P3** | 왜 그 부분이 맞춰졌다고 느꼈나 | 주관식 |
| **P4** | 반대로 "상관없네 / 왜 보여주지" 싶은 부분 | 주관식 |
| **P5** | 나의 상황과 얼마나 맞나 | ①~⑤ |
| **C1** | 어느 쪽이 더 "나의 상황에 맞춰진" 화면인가 | 첫 번째/두 번째/비슷하다 |
| **C2** | 이유 — 요소 4개 + 기존이 이길 수 있는 항목 2개, 어느 쪽을 골랐든 같은 목록 | 복수 + 기타 |
| **C3** | 고른 화면에서 그래도 상관없던 부분 | 주관식 |
| **C4** | 추천이 부담스럽거나 광고처럼 느껴졌나 | 주관식 |

**두 화면을 "첫 번째 · 두 번째"로만 부른다.** 어느 쪽이 기존인지 참가자에게 알리지 않는다.
P2 답은 집계 때 요소로 분류한다 — 요소 이름을 보기로 주지 않는 이유는, 주면 그 자리에서 학습하고 고르기 때문이다.

### 이미지 2장 — `img/`

| 파일 | 내용 |
|---|---|
| `img/home-existing.png` | 기존 슈퍼SOL **보유자** 보험 탭 |
| `img/home-ours.png` | 우리 화면 상태 B (`?state=B`) |

- **같은 폰 프레임 · 같은 크기 · 브라우저 UI 없이** — 하나라도 다르면 블라인드가 깨진다
- **기존 화면의 실명·증권번호는 마스킹** — 저장소가 public 이다. 이름은 "김신한"으로 덮는다
- **보험 건수·보험료를 역할과 맞춘다** — 역할은 "보험 2개 · 월 3만 5천 원"이고 우리 화면 목데이터와 같다

## 아이디어 3 · 보장에너지 vs 보장진단 — 역할 유지, 프로토타입에서 직접 조작, 블라인드 아님

기존 보장에너지는 **우리 프로토타입 안에 재현한 것**을 쓴다 (발표에서 반드시 밝힌다).
이름을 먼저 묻는 순간 정체가 드러나므로 블라인드는 포기하고 **이해도를 실측**한다.
개선한 지점 = 기존 "주요 보장 / 부족 보장" 두 목록을 **연령 기준 우선순위**로 재구성.

| | 문항 | 형식 | 사후 채점 |
|---|---|---|---|
| **T1·T3** | "{이름}"이라는 메뉴가 있다면 어떤 서비스일 것 같은가 | 주관식 | 예측 적중 |
| **T2·T4** | 이름만 보고 눌러보고 싶은가 + 이유 | 3지 + 한 줄 | |
| **T5** | 두 이름 중 무슨 서비스인지 더 잘 짐작되는 쪽 + 왜 | 3지 + 한 줄 | |
| **A1** | 숫자가 무엇을 기준으로 나온 것 같은가 — **카드 누르고 뜨는 첫 페이지만 보고** | 주관식 | 정답/오답/모르겠다 |
| **A2** | 지금 가장 먼저 챙겨야 할 보장은 — **"자세히 진단 보기"로 들어간 뒤** | 주관식 | 정답/오답/답 못 함 |
| **A3** | 왜 그게 먼저라고 생각했나, 화면 어디를 보고 | 주관식 | 화면 근거(나이)/자기 상식/모름 |
| **A4** | 20대·보험 2개인 나한테 맞춰졌다고 느껴지는 부분 | 주관식 | |
| **A5** | 반대로 상관없네 / 왜 보여주지 싶은 부분 | 주관식 | |
| **A6** | 이해 안 되거나 낯선 표현 | 주관식 | |
| **A7** | 써보고 나니 이름이 서비스에 잘 어울리나 + 더 맞는 이름 | 3지 + 한 줄 | |
| **E1·E2** | 또래 비교 소감 / 부담감 — **두 서비스 다 본 뒤** | 주관식 | |
| **D1** | 내 보장 상태를 이해하기 더 쉬웠던 쪽 | 보장에너지/보장진단/비슷 | |
| **D2** | 이유 — 어느 쪽을 골랐든 같은 목록 | 복수 + 기타 | |
| **D3** | 고른 쪽의 아쉬운 점 | 주관식 | |
| **D4** | 써보고 나서 — 더 맞는 이름은 + 왜 | 3지 + 한 줄 | |

- **A1·A2·A3 채점은 화면에서 하지 않는다** — 참가자가 보는 화면에 정답 힌트가 남는다. CSV 의 주관식 답을
  `채점기준.md` 기준으로 **두 사람이 독립 채점**하고 일치율을 적는다. 기준은 데이터를 보기 전에 확정한다
- **A2·A3 짝**이 발표 숫자다 — "기존 n명 / 우리 n명이 먼저 챙길 보장을 맞게 짚었고, 그중 나이 기준을 근거로 든 사람 n명"
- **A2 정답표를 먼저 정한다** — 우리 목데이터의 "꼭 채워야" 항목. 기존 재현 화면의 부족 목록에도 있어야 비교가 성립한다
- **T5 ↔ D4 짝**이 이름 검증 — 이름만 봤을 때와 써본 뒤 답이 바뀐 사람 수
- **A1·A2 는 "먼저 본 서비스" 기준(각 4명)도 따로** 적는다
- E1·E2 를 첫 서비스 직후에 물으면 "이쪽이 다른 거구나"가 새니 두 서비스 다 본 뒤로 뺐다

## 마무리 F1~F3 — 맨 끝

| | 문항 | 형식 |
|---|---|---|
| **F1** | 전체적으로 보험 관련 이용이 더 편했던 쪽 + 왜 | 기존/두 번째/비슷 + 한 줄 |
| **F2** | 두 번째 화면에서 가장 불편하거나 개선이 필요한 부분 | 주관식 |
| **F3** | 반대로 기존 슈퍼SOL 이 더 낫다고 느낀 부분 | 주관식 |

**F2·F3 는 빼지 않는다.** 없으면 "8명 전원 좋다고 했다"가 되고, 그건 발표에서 질문지를 안 보여준 걸로 읽힌다.

## 쓰는 법

1. **진행자가 시작 화면에서** 참가자 번호 · 진행자를 입력한다. 순서는 자동, 손으로 바꿀 수 있다
2. 표지 페이지에서 과업을 안내하고, 역할 화면을 참가자가 읽게 한다
3. 참가자가 전부 직접 답한다. 진행자는 화면에 손대지 않는다 — Task2 에서는 특히 "눌러보세요" 금지
4. 참가자 1명이 끝나면 **CSV 내려받기** → "다음 참가자"

## CSV 를 받는 경로

| 어디서 여나 | CSV 버튼이 하는 일 |
|---|---|
| **배포한 링크** (9/11 진행용) | 바로 파일로 저장된다 |
| `survey.html` 파일을 직접 열기 | 바로 파일로 저장된다 |
| 아티팩트 링크 | 저장이 막혀 있어 **복사창**이 뜬다 — 복사해서 엑셀에 붙여넣는다 |

판정은 호스트 이름이 아니라 **저장을 실제로 시도해 보고** 한다.

## ⚠️ 참가자 1명 끝날 때마다 CSV 를 받는다

제출된 응답은 **그 브라우저의 localStorage**(`sol_survey_v2`)에만 쌓인다. 시크릿 모드·데이터 정리·다른 브라우저로 열면 유실이다.

## CSV 열 구성 — 순서가 아니라 정체로 나간다 (74열)

```
참가자, 먼저(기존/우리), 진행자, 시작, 종료,
B1, B1_이유, B2,
Q0_기존, Q0_두번째, Q1_기존, Q1_두번째, Q2, Q3,
G1, G1b, G2, G3, G4, G5, G5_이유, G6, G7,
기존_P1 … 기존_P5, 우리_P1 … 우리_P5,
C1, C2, C2_기타, C3, C4,
기존_T1, 기존_T2, 기존_T2_이유, 우리_T1, 우리_T2, 우리_T2_이유, T5, T5_이유,
기존_A1 … 기존_A7, 기존_A7_이유, 우리_A1 … 우리_A7, 우리_A7_이유,
E1, E2, D1, D2, D2_기타, D3, D4, D4_이유,
F1, F1_이유, F2, F3
```

- `C1` 의 "첫 번째/두 번째"와 `T5`·`D1`·`D4` 의 서비스 이름은 전부 **기존/우리로 풀어서** 적는다
- `Q0` 는 보기 글자("둘 다 찾았다" 등)로, `Q1`·`P5` 는 숫자로 나간다
- 복수 선택은 `|` 로 이어 붙는다. 안 밟은 분기(G2~G7)는 **N/A**
- 화면에서 B1~B7 로 보이는 두 번째 서비스 문항도 CSV 에서는 정체 기준 `기존_A…`/`우리_A…` 다

**집계**: 도수만 센다. 척도(Q1·P5)는 ④⑤ 도수. 평균 내지 않는다.
발표에서는 **"보유자 역할을 부여한 평가"** · **"기존 보장에너지는 프로토타입 안에 재현"** 을 명시한다.

## 고칠 때

문항은 `survey.html` 안 배열에 있다 — `B`(배경), `PR`·`G1`·`G_USED`·`G_UNUSED`(아이디어1),
`P`·`C`(아이디어2), `T`·`T5`·`A`·`E`·`D`(아이디어3), `F`(마무리). 표지 문구는 `IDEAS`, 역할 문구는 `ROLE`·`ROLE2`.
`docs/정성평가/평가도구/평가지.md` 를 먼저 고치고 여기 반영한다.

| 키 | 뜻 |
|---|---|
| `{name}` | 문항 문장 안에서 서비스 이름(보장에너지/보장진단)으로 치환 |
| `guide` | 문항 위 안내 상자 — 참가자에게 보이니 참가자 말투로 쓴다 |
| `required:true` | 답을 고르기 전엔 넘어갈 수 없다 |
| `branchKey:true` | 이 문항 답으로 이후 문항 세트가 갈린다(G1b) |
| `branch:'used'/'unused'` | 이 문항이 어느 분기에 속하는지 — 반대 분기면 CSV 에 N/A |
| `follow:{q,ph}` | 선택형 뒤에 붙는 한 줄 주관식 → CSV `_이유` |
| `orderOpts` / `svcOpts` | 보기가 순서/서비스 이름 → CSV 에서 기존/우리로 변환 |
| `type:'pair'` | 대응비교(기존/두 번째 각각) → CSV `_기존`/`_두번째` · `nonum` 숫자 숨김 · `textVal` 보기 글자로 출력 |
| `thumbs:true` | 문항 위에 두 화면 썸네일 |
| `other:true` | 기타 + 입력칸 |
| `orderNote:true` (IDEAS) | 표지에 이번 참가자의 앱 순서를 표시 |
| `mod:{…}` | 진행자 판정 칸 — **지금은 쓰지 않는다.** 넣으면 참가자 화면에 보인다 |
