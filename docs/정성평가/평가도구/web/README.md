# 평가지 웹 — 참가자 직접 입력용

`survey.html` 파일 하나다. 서버·빌드·설치가 필요 없다. 더블클릭하면 브라우저에서 열린다.

## 쓰는 법

1. **진행자가 시작 화면에서** 참가자 번호 · 보유 여부 · 순서를 입력한다
   → 이 세 가지가 없으면 나중에 A/B 분리 집계를 못 한다. 안 채우면 시작 버튼이 안 눌린다
2. **참가자가 직접** 문항에 답한다 (주관식 포함)
3. **진행자는 노란 칸만** 손댄다 — 과제 성공/실패, 정오 판정
4. 참가자 1명이 끝나면 **CSV 내려받기** → "다음 참가자"

## CSV 를 받는 두 가지 경로

| 어디서 여나 | CSV 버튼이 하는 일 |
|---|---|
| **`survey.html` 파일을 직접 열기** (권장) | 바로 파일로 저장된다 |
| 아티팩트 링크 | 저장이 막혀 있어 **복사창**이 뜬다 — 복사해서 엑셀에 붙여넣는다 |

9/11 당일에는 **파일을 직접 여는 쪽**을 쓴다. 아티팩트 링크는 회의에서 보여줄 때 쓴다.

## ⚠️ 참가자 1명 끝날 때마다 CSV 를 받는다

응답은 **그 브라우저의 localStorage 한 곳**에만 쌓인다. 시크릿 모드·데이터 정리·다른
브라우저로 열면 유실이다. 리허설 체크리스트 §1 과 같은 규칙이다.

## 상태 A/B 분기

| | 문항 수 |
|---|---|
| 보유(state=B) | 32 |
| 미보유(state=A) | 28 |

미보유자에게는 `[보유만]` 문항(Q8·Q9·Q10·Q11)이 **화면에 아예 안 나온다.**
CSV 에는 그 칸이 **`N/A`** 로 찍힌다 — 빈칸이 아니다. 무응답과 구분해야
"미보유자가 못 찾았다"가 실패로 잘못 집계되지 않는다.

Q12·Q17 은 상태에 따라 **보기와 질문이 다르다** (다른 화면을 보기 때문).

## 참가자별 보기 순서 뒤집기

Q13 은 참가자 번호가 **홀수(P1·P3·P5·P7)면 보기를 역순**으로 보여준다.
정답 보기가 늘 맨 위에 있으면 피로가 쌓인 참가자가 첫 보기를 찍기 때문이다.
채점기준 §5 에 있는 규칙을 자동으로 처리한다.

## CSV 열 구성

```
참가자, 보유여부, 순서, 진행자, 시작, 종료,
D1, D2, D3,
Q1, Q1_진행자, Q2, ...
Q8_기존, Q8_두번째, Q8_진행자,     ← 대응비교는 두 열로 갈린다
Q26_청구찾기, Q26_보장이해, ...      ← 항목별 비교는 항목마다 한 열
```

엑셀에서 `보유여부` 로 필터하면 A/B 분리 집계가 바로 된다.
**척도는 평균 내지 않는다** — ④⑤ 도수만 센다 (채점기준 §2).

## 고칠 때

문항은 `survey.html` 안 `const Q = [...]` 배열 하나에 다 있다.
`docs/정성평가/평가도구/평가지.md` 와 1:1 로 맞춰 뒀으니 **문서를 먼저 고치고** 여기 반영한다.

| 키 | 뜻 |
|---|---|
| `only:'B'` | 보유자만 (미보유는 건너뛰고 CSV 에 N/A) |
| `split:true` | A·B 분리 집계 대상 (렌더는 같고 집계만 나눔) |
| `flip:true` | 참가자 번호 홀수면 보기 역순 |
| `optsA`/`optsB` | 상태별로 보기가 다름 |
| `qA` | 상태 A 에서 질문 문장 자체가 다름 |
| `mod:{...}` | 진행자 판정 칸 (노란 영역) |
