## Q1. (디자이너) "고령 가입자가 많은 보험 탭인데 시스템 글자 크기 키운 사용자는?"

→ 9/11 검증 범위를 **20대 신규 진입자로 한정**했다. 실서비스 전환 시 과제로 명시
(`text-size-adjust` 현황 포함).

## Q2. (개발자) "키워드 매칭 에이전트, 순서 바꿔 물으면 빠져나가죠?"

→ **의도된 설계다** — 실제 LLM 은 테스트 통제 변수라 일부러 뺐다. 응답이 고정이어야
참가자 간 조건이 같다. 수세가 아니라 실험 설계 근거로 답한다.

## Q3. (PM) "구조 개선이 좋아졌다는 걸 회사 언어로 말하면?"

→ 사용자 관점 문구 규칙은 앱 안 이야기고, Q&A 용 번역을 따로 준비:
"찾다가 포기하는 사용자 감소 = 상담·콜센터 유입 감소, 보유 계약 확인 실패 감소 =
중복 가입 민원 감소" 등. **수치 약속은 하지 않는다** (n 이 작다).

## Q4. (PM) "n수가 그걸로 결론이 되나요?"

→ 통계적 결론이 아니라 **구조 가설의 1차 검증**으로 포지셔닝. 과제 성공률 + 주관 평가
2종을 쓰는 이유(한쪽만 기계 측정하면 편향)를 같이 설명하면 오히려 강점이 된다.
