# 9/20 발표 계획

> 2026-08-31 팀장 구술을 정리. **무엇을 어떤 순서로 보여줄지**가 문서에 없어 만들었다.
> 예상 질문 답변은 `9-20-발표-QA.md` 가 담당한다 — 이 문서는 **구성과 준비물**이다.

## 0. 이 과제의 성격

**신한라이프 일경험 사업 · 마케팅 직무 과제.** 10팀 중 3팀 수상.

⚠️ **다른 팀은 시안·기획서로 낼 가능성이 높다.** 동작하는 앱은 차별점이지만,
"왜 마케팅 과제에 개발을 했나"에 답하지 못하면 직무와 무관한 곳에 힘을 쏟은 것으로
읽힌다. 답은 `9-20-발표-QA.md` Q4-1 에 있다 — **만든 것이 목적이 아니라 검증 도구다.**

### ⚠️ 심사 대상은 **배포된 앱**뿐이다 (2026-08-31 팀장)

깃 저장소를 제출하는 과제가 아니다. 심사위원이 보는 것은 **발표 · 영상 · QR 로 연 앱**
셋뿐이다. 여기서 우선순위가 갈린다:

| | 심사에 보이나 | 그래서 |
|---|---|---|
| 폰에서 보이는 화면·동작 | ✅ | **여기에 시간을 쓴다** |
| 코드 품질·테스트·CI | ❌ | 우리가 안 깨지려고 쓰는 것 — 자랑거리가 아니다 |
| 문서 (이 문서 포함) | ❌ | 팀 내부용 |

⚠️ 발표에서 **"테스트 53개"·"CI 8종" 같은 개발 지표를 말하지 않는다.** 마케팅 직무
과제에서 그건 직무와 무관한 이야기로 들린다. 개발 이야기는 Q4-1 처럼
**"왜 만들었나(검증 도구)"** 로만 한다.

⚠️ 반대로 **QR 로 열었을 때 깨지는 것은 곧바로 감점이다.** 코드가 아무리 튼튼해도
폰에서 상태바가 두 개로 보이면 그것이 평가 대상이다 (실제로 있었던 일 — #115).

심사위원은 우리가 몇 번 확인했는지 모른다. **깨진 화면이 남아 있는지만 본다.**

⚠️ 지금까지 나온 실기기 문제는 **전부 팀장이 폰에서 찾아 고쳤다** — 상태바 두 개(#115),
홈화면 화질, 스플래시 속도, S3-F 키보드, S2-A 아이콘 누락. 브라우저 확인만으로는
안 잡히는 것들이라, **폰 확인이 이미 개발 과정에 들어와 있다.**

### ⚠️ 개선 범위 — 보험 탭 안쪽만

**신한슈퍼쏠 앱 안에서 보험 탭만 개선한다.** 범위는 A+B 두 곳이다
(`01_as-is/screen-inventory.md`):

| | 범위 | 우리가 만든 것 |
|---|---|---|
| A | 금융 › 보험 | S1 계열 · S3 진단 · S4·S5 청구 |
| B | 상품 › 보험 | S2 상품 찾기 · S6 상품 상세 |

**범위 밖 — 손대지 않는다**:
- **메인 홈** (계좌·카드·땡겨요·이벤트) — 다른 팀 영역이다. AS-IS 그대로 재현만 한다
- **탭바 구성** (홈·금융·상품·혜택·주식)
- **금융 탭의 은행·카드·증권** · **상품 탭의 다른 카테고리**
- **보험 탭에 도달하는 경로** — "금융 → 보험" 2클릭은 AS-IS 구조다

⚠️ **심사는 신한라이프 직원이 한다.** 보험 탭 밖을 바꾸자는 제안은
**월권으로 읽힌다** — 은행·카드 담당 영역이다. "보험을 홈에 올리자" 같은 말은
하지 않는다.

⚠️ 반대로 **홈을 AS-IS 그대로 둔 것이 범위를 지켰다는 증거**다. 심사위원은
매일 이 앱을 보는 사람들이라 우리가 어디를 건드렸는지 바로 안다.

## 1. 발표 서사

**대상**: 슈퍼쏠은 쓰지만 **보험 탭은 안 쓰는** 20~30대.

**문제**: 이들에게 보험은 "필요한 건 아는데 뭘 봐야 할지 모르는" 영역이다.
AS-IS 보험 홈은 첫 화면이 광고 배너·추천 위주고, "내 보험 조회"는 3스크롤 아래
12개 그리드에 묻혀 있다 (`01_as-is/screen-inventory.md` 01번).

**제안 구조**:

| 축 | 목표 | 아이디어 | 화면 |
|---|---|---|---|
| **신규 유치** | 보험 탭에 더 오래 머물게 · 더 쉽게 조회하게 · 가입까지 | 2 보험 메인 | S1 계열 |
| | 내 보장이 뭐가 비었는지 보기 쉽게 | 4 보장 진단 | S3 계열 |
| | 맞는 상품을 찾게 | 1 상품 찾기 | S2 · S6 |
| **고객 유지** | 끌어들인 고객이 다른 보험사로 안 나가게 | 3 청구 알림 | S4 · S5 |

**한 줄**: 신규 유치 3개 + 고객 유지 1개로 보험 탭을 다시 설계했다.

⚠️ **아이디어 3(청구)은 유치가 아니라 유지 맥락으로 말한다.** 순서를 섞으면
"왜 청구부터 이야기하나"가 된다. 앞의 셋으로 끌어들이고, 마지막 하나로 붙잡는다.

⚠️ "유치·유지"는 **발표 언어**다. 앱 화면에는 회사 관점 문구를 쓰지 않는다
(CLAUDE.md 문구 규칙 — "노출 증대"·"가입 전환" 금지).

### 1-1. 네 번째 축 — 톤

아이디어 4개와 별개로 **화면 전체를 관통하는 규칙**이 하나 더 있다. 발표에서
질문을 기다리지 말고 **먼저 말한다** (Q4-2 는 그 백업이다).

AS-IS 는 이렇게 말한다 (R-18):

> "또래 대비 **96% 부족해요**" (빨강) · "보장이 **텅 비었어요!**"

우리는 이렇게 말한다:

> "지금 채우면 좋아요" · "여유 있을 때 봐도 돼요" ·
> "이미 준비돼 있어요" · "지금은 서두르지 않아도 돼요"

**같은 10개 항목인데 급한 것과 급하지 않은 것을 나눈다.** 20대 1인 가구에게
사망 보장은 텅 빈 게 아니라 아직 필요하지 않은 것이다.

⚠️ **불안 마케팅에 대한 피로**가 이 세대에서 크다. 압박으로 읽히면 탭을 닫는다.
금융 화면에서 단정은 규제 리스크이기도 하다 (변경로그 §3 — "청구할 수 있어요"
같은 단정 표현 금지).

**발표 문장**: *"저희는 불안을 자극해 가입시키는 방식을 의도적으로 뺐습니다.
판단은 사용자가 합니다."*

## 2. 차별점 — 제안이 아니라 결과

다른 팀이 *"이렇게 하면 좋아질 것이다"* 를 말할 때, 우리는
**"실제로 태워 봤더니 이렇게 나왔다"** 를 말한다. 9/11 사용자 테스트가 그 근거다.

**발표에 쓰는 수치는 정성평가에서 나온다** — 과제 성공률 + 평가지 2종.
참가자를 직접 태워서 얻은 결과이고, 이것이 주 근거다.

⚠️ **계측(`/export`)은 발표 자료가 아니다.** 심사위원은 진행자 화면에 못 들어간다
(숨은 입구 + URL 비공개). 계측은 **우리가 "어디서 헤맸나"를 볼 때** 쓰는 내부
도구이고, 거기서 나온 관찰을 발표에서 말할 수는 있어도 화면을 보여줄 일은 없다.

→ 그래서 #102(CSV 가 빈 파일)는 **심사 리스크가 아니다.** 분석이 편해지는 정도라
   우선순위가 낮다.

## 3. 발표 구성 — 10분

발표 10분 + 평가. 초 단위로 짜야 넘치지 않는다.

| 순서 | 시간 | 내용 |
|---|---|---|
| 1 | 90초 | **도입** — 대상과 문제. "슈퍼쏠은 쓰는데 보험 탭은 안 쓴다" · AS-IS 는 내 보험 조회가 3스크롤 아래 |
| 2 | 30초 | **광고 영상** |
| 3 | 60초 | 아이디어 2 보험 메인 — 0건과 2건이 **다른 화면을 본다** |
| 4 | 90초 | 아이디어 4 보장 진단 — **핵심.** 티어 4단 + 톤(§1-1) |
| 5 | 45초 | 아이디어 1 상품 찾기 — 목록보다 조건 먼저 |
| 6 | 75초 | 아이디어 3 청구 알림 — **유지 축.** 시연 도입부(알림→앱) |
| 7 | 120초 | **검증 결과** — 9/11 성공률 + 평가지 |
| 8 | 30초 | 마무리 — 확장 경로(Q5 의 축→화면 매핑) |
| | **540초** | 여유 60초 — QR 안내·돌발 상황 |

⚠️ **아이디어에 쓰는 시간은 270초(4.5분)뿐이다.** 4개를 균등 배분하면 각 67초라
아무것도 못 보여준다. 위 배분은 **4번(진단)을 주인공**으로 두고 나머지를 줄인 것이다.

⚠️ **검증 결과에 120초를 뺐다.** 이게 다른 팀과 갈리는 지점이라 여기서 줄이면
차별점이 사라진다. 아이디어 설명을 줄이는 게 낫다.

### 3-1. 30초 광고 영상

**아직 미착수.**

**콘티 방향** — 30초에 4개를 넣으면 각 7.5초라 아무것도 안 남는다.
**한 사람의 이야기로 꿰는 편**이 낫다:

```
0-8초    병원에서 결제 → 폰에 알림이 온다        (아이디어 3 · 유지)
8-16초   앱을 열어 보니 내 보장이 뭐가 비었는지   (아이디어 4 · 진단)
16-24초  나에게 맞는 걸 찾아본다                 (아이디어 1 · 상품)
24-30초  로고 + 한 줄
```

이러면 4개가 다 나오되 **각각을 설명하지 않는다** — 한 사람이 겪는 흐름으로 보인다.
아이디어 2(보험 메인)는 배경으로 계속 깔리므로 따로 시간을 안 써도 된다.

정할 것:
- [ ] 위 콘티로 갈지, 한 아이디어만 깊게 갈지
- [ ] 화면 녹화 vs 모션 그래픽 — 앱이 실제로 동작하므로 **실화면을 쓸 수 있다**
- [ ] 제작 담당·마감
- [ ] 내레이션 유무 (발표 중 재생이라 자막만으로도 됨)

⚠️ **9/10 프리즈 전에 화면을 찍어 둔다.** 프리즈 후엔 화면이 안 바뀌므로 미리 찍어도
최종본과 같다. 9/11 이후에 몰면 8일 안에 촬영·편집을 다 해야 한다.

⚠️ **문구 규칙이 영상에도 걸린다** — "개선안"·"솔루션"·"MVP"·팀명 금지,
회사 관점 문구 금지. 영상은 발표 자료라 앱보다 느슨하지만, 심사위원이 자사
상품 담당자일 수 있어 **상품 조건을 단정하는 표현은 피한다.**

### 3-2. QR 현장 시연

심사위원과 청중이 **직접 폰으로 열어 본다.**

| | |
|---|---|
| 링크 | https://supersol-insurance-app.vercel.app |
| 진행자 화면 | 홈 헤더 "김신한님" **5번 연속 탭** → `/demo` |
| 계측 | `/export` (URL 비공개로만 보호 — 비밀번호 없음) |

**이미 대응한 것** (변경로그 기록):
- S6-A 상품안내 탭에 **가상값 면책** 추가 — 심사위원이 아무 상품이나 열어 볼 수
  있어서다. 자사 9개는 실제 신한라이프 상품명을 쓰는데 상세 조건은 가상값이다
- 상품 상세값 **26개 전 상품** 채움 — 어느 걸 열어도 빈 화면이 안 나오게
- `:active` 눌림 피드백 — 폰에는 hover 가 없다

**언제 띄우나** — 10분 발표라 타이밍이 곧 리스크다.

| 시점 | 문제 |
|---|---|
| 발표 시작 | 청중이 폰을 보느라 **발표를 안 듣는다** |
| 발표 끝 | 만져 볼 시간이 없다 — 평가로 바로 넘어간다 |

→ **아이디어 3(75초, 순서 6번) 직전에 띄우는 것**을 제안한다. 이유:

1. 도입·영상·아이디어 2·4 로 **맥락이 이미 쌓인 뒤**다 — 무엇을 볼지 알고 연다
2. 청구 알림은 **직접 눌러 봐야 이해되는** 흐름이다 (알림 → 앱 → 팝업)
3. 뒤에 검증 결과 120초가 남아 있어, **만져 보면서 결과 설명을 들을 수 있다**

⚠️ 슬라이드에 QR 을 계속 띄워 두지 말고 **그 구간에만** 크게 띄운다. 계속 떠 있으면
발표 내내 폰을 본다.

**아직 안 한 것**:
- [ ] QR 코드 생성 — 슬라이드에 넣을 것 (인쇄물은 선택)
- [ ] **홈 화면 추가 안내** — QR 로 열면 사파리 주소창이 남는다. 전체화면으로 보려면
      "공유 → 홈 화면에 추가"가 필요한데, 심사위원에게 그걸 시킬 수는 없다.
      **주소창이 있는 채로 보여도 괜찮은지 확인** (393 고정 폭이라 레이아웃은 유지됨)
- [ ] 동시 접속 확인 — 여러 명이 같이 열었을 때. Vercel 정적 배포라 문제는 없을
      것으로 보이나 미검증
- [ ] **시연 중 계측이 섞인다** — 심사위원 탭이 9/11 참가자 데이터와 같은
      localStorage 에 쌓인다. 발표 전에 `/export` 에서 기록을 비우거나, 9/11 데이터를
      먼저 내보내 두어야 한다
